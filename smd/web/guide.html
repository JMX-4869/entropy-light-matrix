这是什么

一个群星（Stellaris）模组管理工具。核心是三件事：

  1. 查冲突 —— 扫描所有模组，找出同名对象重定义、文件覆盖、本地化键打架、依赖缺失、版本不符。
  2. 排顺序 —— 按模组性质分层（前置库 → 大型重做 → 内容 → UI → 小调整 → 汉化 → 覆盖层），再叠上作者在工坊描述里写的排序要求。
  3. 打补丁 —— 冲突能合并的，生成一个补丁模组把它们缝起来；不能合并的，让 AI 给出取舍建议。
它不会做什么：不会自动停用你的模组，不会改游戏本体文件。 所有写操作（改排序、装补丁）都要你点确认。

两个版本的区别

版本说明体积
完整版 pywebview + Edge WebView2 界面，能弹文件夹选择框、能开新窗口 ~15 MB
轻量版 纯 tkinter 界面，功能和完整版一样，但界面朴素、没有主题 ~13 MB

两个版本用的是同一套核心代码，可以同时装。

三分钟上手

第一次打开，按这个顺序走。

1
看「总览」顶部的路径对不对 正常情况下会自动探测到游戏目录和用户数据目录。 如果显示「未找到」，看下一节。
2
点「开始检测」 扫一遍所有模组，大约 20 秒。会给出一个健康分（0~100）和冲突清单。
3
去「最优方案」点「重新计算」 它会给出一个建议的加载顺序和推荐启用的模组。
4
看「加载顺序」，确认无误后点「应用方案」 写入的是启动器的 playset，不动你的模组文件。
5
（可选）去「补丁工坊」处理剩下的冲突 能用本地规则的先跑本地（免费），剩下的再考虑 AI。
重要：应用方案之前建议先在启动器里存一份当前的 playset。 写错了还能切回去。

路径怎么填

设置 → 路径。大部分情况自动探测就够了，这一节只在探测失败时看。

三个必填项

项标准位置填错会怎样
用户数据 C:\Users\你\Documents\Paradox Interactive\Stellaris 读不到 mod 列表、存档、日志
游戏目录 …\steamapps\common\Stellaris 读不到游戏版本、DLC 清单
模组路径 …\steamapps\workshop\content\281990 工坊模组一个都扫不到
本地模组不用填这里。它在用户数据目录下的 mod\， 只要「用户数据」填对就自动识别。

全面扫盘

路径卡片里有个「全面扫盘」按钮。它会逐盘找上面这三样，找到的列出来， 每条带「用这个」，点一下直接写进配置。

  • 盘符可以多选（按住 Ctrl），不选就全扫
  • 三块盘大约 5 秒，机械硬盘会慢一些
  • 找的是：含 Stellaris.exe 的目录、含 save games+mod+logs 的目录、workshop/content/281990

学习版 / 便携版

有些整合版把存档放在游戏目录里，或者根本没有启动器数据库。 设置页有个「学习版 / 便携版专用」折叠区，五项都能单独指定：

项留空时用
存档目录用户数据目录/save games
启动器数据库用户数据目录/launcher-v2.sqlite
日志目录用户数据目录/logs
崩溃转储目录用户数据目录/crashes
额外模组目录不扫（可以填多个，用 ; 分）

另外，探测游戏目录时会往上下一层递归找含「save games + mod + logs」三样的目录， 所以放在游戏目录里的存档也能自动认出来。

模组列表

列出所有扫到的模组，工坊的和本地的都在。

  • 启用状态：来自启动器的 playset
  • 文件数 / 大小：点开能看到具体哪些文件
  • 工坊 ID：可以点开直接跳 Steam 页面
  • 本地 / 工坊标签：本地模组没有工坊 ID
「文件缺失」是什么意思：描述符（.mod）里写的 path 指向的目录不存在。 通常是你取消订阅了但描述符还在，或者整合包挪过位置。

冲突检测

这是整个软件的核心。跑一次大约 20 秒。

它在查什么

类型含义严重度
文件覆盖冲突 两个模组有同名文件，后加载的整个盖掉前面的 高
脚本对象重定义 两个模组定义了同名对象（建筑、科技、特质…），后加载的生效 致命 / 严重
本地化键冲突 同一个翻译键，两个模组给了不同译文 中
版本兼容问题 模组的 supported_version 和游戏版本对不上 中
依赖缺失 模组声明需要另一个模组，但那个没装或没启用 严重
文件完整性问题 描述符里写的东西实际不存在 低

健康分怎么算的

从 100 往下扣：致命 −8、严重 −4、中等 −1.5、轻微 −0.5，再按模组总数做一次归一化。 分数只是参考，真正要看的是列表里具体的条目。

列表操作

  • 点条目展开，能看到具体是哪两个模组、哪个文件、哪一行
  • 顶部「严重度」「类型」标签点一下就是筛选
  • 搜索框可以搜对象名 / 模组名 / 关键词
  • 「已被补丁解决」的条目默认会隐藏 —— 打完补丁回来看不见才算修好了
「问题总数 510 条」不代表你的游戏一定崩。 大部分是低严重度的文件覆盖，游戏自己能处理。真正要管的是致命和严重。

最优方案

点「重新计算」才会算，不会自动跑（几十个模组要算几秒）。

它给出什么

  • 推荐启用的模组：被完全覆盖、或者和别的模组硬冲的，会建议停用
  • 建议的加载顺序：分七层，见下一节
  • 健康分变化：应用后预计能从多少涨到多少
它只是建议。点「应用方案」才真的写进启动器。 模组停用需要你自己在启动器里操作 —— 这个软件不会自动停用任何模组。

加载顺序

分层的依据是「谁该在谁后面生效」。

七个层

层典型模组为什么排这
① 前置框架 / 基础库Better Performance、Universal Resource Patch别人依赖它，必须最早
② 大型机制重做Gigastructural、NSC3、ACOT改的东西最多，要压在别人下面
③ 常规内容星球多样性、传统扩展加内容但不改机制
④ 界面 UIUI Overhaul Dynamic、Topbar要盖住上面所有层改的界面
⑤ 兼容补丁 / Bug 修复各种 Patch、Bug Fixes专门修别人冲突的，得在前面之后
⑥ 小型调整数值调整、立绘、语音、Trait 槽零碎改动，放最后面不惹事
⑦ 本地化 / 汉化鸽组汉化、模组翻译包必须最后，否则被原文覆盖
⑧ 最终覆盖层名字里带 Override 的作者明确要求最后

层为什么会被打散

你可能会看到「大型重做」出现在「UI」后面又回来。这是正常的： 作者在工坊描述里写了「请把我和 XX 排在一起」这类要求， 软件会照做，而那条要求可能跨层。

排序要求从哪读的：模组的 descriptor.mod 没有描述字段， 所以排序要求只存在于Steam 工坊页面。软件会批量拉取工坊描述（一次 50 个）， 解析里面的「排序要求 / Load Order」段落。 第一次拉会慢一点，之后缓存 7 天。

怎么确认排对了

看每层的起止位置是不是递增的。比如：

前置底座   0–1
大型重做   2–32
常规内容   16–38
界面 UI     18–47
小型调整   23–65
汉化        66–72
Override    73

起点依次变大就对了。区间重叠是跨层约束造成的。

补丁工坊 · 五种方式

顶部有五个模式，按你的情况选。

模式适合什么花钱吗
✦ AI 生成补丁 单个复杂冲突，需要理解设计意图的 会
⊙ 本地自动补丁 文件覆盖合并、本地化补齐这类机械活 免费
✎ 我自己写 你会写脚本，想自己改 免费
⚡ 批量生成补丁 几十条冲突一次处理 看用哪个引擎
🌐 一键翻译 给模组补中文 会
生成 ≠ 生效。生成的只是草稿，还要点「保存成补丁模组」才会写成真正的模组文件。 批量生成的可以在最后一键全部保存。

AI 生成补丁

选一个冲突 → 看它把什么发给 AI → 点生成 → 校验 → 保存。

流程

1
在列表里选一条冲突 只有「同名对象重定义 / 文件覆盖 / 汉化冲突」这三类能打补丁。 依赖缺失、版本不符这类补丁修不了。
2
点「预览要发送的内容」 这一步不联网、不花钱。会显示将要发送的完整 prompt、 每个文件发了多少行（被裁剪的会标出来）、以及 token 数。
3
点「生成」 AI 返回补丁代码，软件会做语法校验和引用校验。 有问题会带着错误重试，最多 3 轮。
4
看校验结果，点「保存为补丁模组」 有致命问题的保存会被拒绝 —— 那是保护你，不是 bug。

AI 目标怎么选

  • 尽量让双方功能都保留：默认，适用于大部分情况
  • 优先保留某一个模组：在「补充说明」里写清楚保留谁
  • 只修语法/引用错误：不改变设计意图

批量生成

几十条冲突一次跑。这里有 token 预估和自校准。

两个引擎

引擎能处理花费
本地规则 文件覆盖合并、本地化补齐等机械可判定的类型。 看不懂的会跳过并如实报告，不会瞎猜。 免费，几秒完成
AI 生成 所有选中的目标，包括需要理解语义的 按 token 计费

操作顺序

  1. 选引擎
  2. 看列表上方的四个数字：已选 / 本地可处理 / 需要 AI / 预计产出
  3. 用「只选本地能处理的」或「只选需要 AI 的」快速筛
  4. 看「预估消耗」那行，心里有数了点「开始批量生成」
  5. 跑完看结果，点「全部保存为补丁模组」
推荐用法：先用本地引擎跑一遍（免费，能修掉一半多）， 再切到 AI 引擎，点「只选需要 AI 的」处理剩下的。

一键翻译

给没汉化的模组补中文。

流程

  1. 选目标语言（默认中文）
  2. 看统计：「待翻译 306 条 / 预估 9 万 token」
  3. 点开始，确认弹窗里会显示预估金额
  4. 跑完可以点「校验译文」看覆盖了多少键
翻译是单独的模组。不会改原模组的文件，生成的是一个本地化补丁模组。 所以它在加载顺序里必须排在最后（汉化层）。

点侧栏「AI 接入」。

要填什么

字段说明

API KeyOllama 不需要

Ollama（本地模型）

不需要花钱，但需要你本机跑着 Ollama。

ollama serve
ollama pull qwen2.5:14b

然后在界面里选 Ollama，模型名填 qwen2.5:14b。 本地模型处理长 prompt 会比较慢，14B 以下的模型生成的补丁质量通常不太行。

配好之后先点「测试连接」。那一按钮会真发一个最小请求， 验证 key、地址、模型名三样都对。

token 预估

所有要花钱的地方都会先给预估。

三处会显示

位置显示什么
批量生成补丁 「开始批量生成」按钮下方：约 N 万 token + 粗算金额
单条 AI 补丁 预览 prompt 时的顶部：约 N token / N 字符
一键翻译 确认弹窗里：约 N 万 token + 粗算金额

怎么估的

批量补丁：真跑前 5 条的 prompt 构造（只读文件、不联网），取平均再乘总数。 前 5 条各不相同，比拿一条乘总数靠谱；全跑一遍又太慢。

自校准

跑完一批之后，软件会用「实际 ÷ 原始估算」的比值修正系数， 下次预估就乘上它。跑得越多越贴实际。

系数存在 %LOCALAPPDATA%\StellarisModDoctor\ai_token_ratio.json。

跑完会显示真实用量（服务商返回的 usage，不是估算）， 并和预估并排。如果差得远，下一次的预估会自动修正。

实际数字参考

一台装了 97 个模组、271 条冲突的机器上：

补丁候选      114 条
每条输入      约 11734 token
全选预估      约 140 万 token（≈ ¥7）
勾 10 条      约 12 万 token
翻译 306 条   约 9 万 token

先只勾几条试试，确认效果满意再批量跑，比一把梭稳。

隐私边界

这个软件默认不会把你的模组内容发出去。

「允许发送模组内容」默认是关的。 不开这个开关，AI 功能会直接拒绝，而不是偷偷发。

开关打开后会发什么

  • 冲突涉及的那几个文件的内容（会被裁剪，预览里能看到发了多少行）
  • 冲突的描述、涉及的模组名
  • 不会发：你的存档、账号信息、其它模组的文件

三个隐私开关

开关作用
允许发送模组内容总闸。关着 = 所有 AI 功能不可用
脱敏路径把 Windows 用户名替换成占位符
只发必要片段每个文件只发冲突所在的那一段，不是整个文件

前两个默认关，第三个默认开。

DLC 管理

显示你有多少 DLC、哪些启用了。

这个页面只读。启停 DLC 要在 Steam 或启动器里操作 —— 直接改 dlc_load.json 容易和 Steam 打架。

运行时监控

游戏跑着的时候看内存、看有没有模组被 Steam 偷偷更新。

两项检查

  • 内存预警：超过阈值弹告警。群星加模组最容易崩在内存
  • 侦测工坊模组变动：游戏运行中被更新模组是存档损坏高危操作
「侦测工坊模组变动」需要先填好工坊路径。 没填路径这个开关等于空转。设置页把路径扫出来后，再回来开这个。

崩溃与日志

游戏崩了之后来看这两个页面。

崩溃报告

读 用户数据/crashes/ 下的崩溃转储，解析出出错的模组和文件。 可以点「AI 分析最近崩溃」让它读一遍日志给出结论。

日志分析

读 error.log / exceptions.log， 归类出重复报错、缺失资源、脚本语法错误。

日志只保留最近一次运行的。群星每次启动会清空 error.log， 所以崩溃之后别急着重开游戏，先来这里看。

扩展（奇点协议）

扩展是独立进程，不装也能正常用主程序。

奇点协议 = OGAS 控制台

安装包里自带。装完到「扩展」页能看到它。

用法

1
先单独下载 OGAS 它是 GPL-3.0 的独立项目，不随本软件分发。
地址：https://github.com/V2t-Nostalgia/OGAS
2
告诉扩展 OGAS 装在哪 把目录路径写进
%LOCALAPPDATA%\StellarisModDoctor\dlc\singularity-protocol\runtime\ogas_home.txt
一行，只有路径。或者设环境变量 SMD_OGAS_HOME。
3
点「启动」 会开一个控制台窗口。等它打印出 listening on 那一行。
4
点「打开控制台」 在软件自己的窗口里打开 OGAS 界面，不是浏览器标签页。
OGAS 本体要先配好模型才能干活。 进去之后先到「模型配置面板」填供应商和密钥，否则它只会显示一片 `--`。

常见问题

点了没反应 / 界面一片空白

看顶部有没有红色横条。有的话把上面的字发出来 —— 那是未捕获的异常，红条上会有文件名和行号。

扫不到任何一个模组

  1. 看「总览」里三个路径是不是都有值
  2. 用户数据目录里应该有 mod\、save games\、logs\ 三样
  3. 用「全面扫盘」让它自己找
  4. 学习版用户看「学习版 / 便携版专用」那一节

排序看起来乱，层被打散

正常。跨层约束（作者要求、依赖、同文件覆盖）会打破层的边界。 判断标准是每层的起点递增。

AI 生成补丁失败

  1. 先确认「允许发送模组内容」开了
  2. 点「测试连接」确认 key 和模型名对
  3. 看报错信息 —— 校验没过会带着错误重试 3 轮，3 轮都失败才算失败

token 预估和实际差很多

第一批发预估会不准（校准系数初始是 1.0）。 跑完一批之后系数会修正，第二批开始就贴了。

应用方案后游戏崩了

  1. 在启动器里切回上一份 playset
  2. 去「崩溃报告」看是哪个模组
  3. 如果是最新游戏版本刚出、大型模组还没更新，那是模组的问题不是排序的问题

桌面图标没了

两个版本共用同一个应用名，卸载其中一个时可能把另一个的快捷方式删掉。 重装一下就好 —— 现在的版本会检查 .lnk 指向的是哪个 exe，不会再误删。

报错对照

你看到的原因怎么办
'str' object has no attribute 'name' 旧版本的解析 bug 升级到最新版
env.xxx is not a function 前端方法没注册 这是软件的 bug，反馈给作者
renderBatchTokens is not defined 旧版本缺 this 前缀 升级到最新版
设置页路径全是空白 旧版本把路径对象序列化成了字符串 升级到最新版
安装时 NameError 旧版本安装脚本的函数定义顺序错了 重新下最新安装包
「程序正在运行，请先退出再安装」 不是 bug，是保护 退出软件再装
双击 exe 没反应 可能被杀软拦了 把安装目录加白名单；或用 cmd 拖进去看真实报错
反馈问题时请带上：
  • 版本号（侧栏左下角，或 --version）
  • 顶部红条上的完整文字（如果有）
  • 你当时点的是哪个按钮、在哪个页面
