## 本次更新

### 1 · 新增：影响成就的模组

玩《群星》想拿成就，最怕的是某个模组悄悄改了游戏逻辑，存档被标记「已修改」，
成就全部作废 —— 而且你往往到通关时才发现。

现在「最优方案」页多了一张卡片，专门查这件事：

* **扫描成就影响** —— 按游戏自带的 `checksum_manifest.txt` 检查实际文件，
  对照 `common` / `events` / `map` 下被校验的目录
* **一键关闭全部启用中的** —— 也可以**自己勾选**要关哪些，不是一刀切
* 每条给出**命中项数 + 具体文件路径**，你能自己判断这个提醒靠不靠谱

实测你这台机器检出 **45 个**（启用中的 44 个）。命中最多的
Gigastructural Engineering 1318 项、ACOT 469 项。

顺带确认了一个常被问的问题：**纯汉化不影响成就** ——
`localisation` 不在游戏的校验范围内。这是读真实 manifest 得出的，不是推测。

「关闭」只是改启用状态，**不会删除你的模组文件**；而且要再点「应用方案」
才真正写入，写入前自动备份、可回滚。

### 2 · 新增：联机校验排查

同一个引擎，用来找**会导致联机校验码不一致**的模组 —— 多人游戏连不上时，
问题通常就出在这里。结果分「可能影响校验 / 未命中校验规则 / 尚不能判断」，
缺文件、压缩包、读取失败都会明确标为未知，**不会当成安全项**。

### 3 · 界面英文化

界面语言切到英文后不再出现中文界面文字。i18n 表扩到 **1155 个键**
（中英完全对齐），覆盖侧栏、总览、最优方案、崩溃报告、补丁工坊、设置等
全部页面，包括 toast 提示、确认对话框、表格表头这些运行时生成的文本。

残留的中文只有**模组名**与**报告文件名** —— 那是你的数据，本就不该翻译。

### 4 · AI 接管 · 全面排查

AI 接管以前只吃「冲突 + 排序」两类数据，结论也只会围绕冲突。
现在汇总 **12 类数据源**：

冲突检测 · 崩溃报告 · 游戏日志 · 成就影响 · 联机校验 ·
运行时监控 · 已有补丁 · DLC 状态 · 加载顺序 · 求解器建议 · 内置知识库

关键在**交叉关联** —— 单看一类只能得表层结论，病因常在交叉点上
（崩溃栈里的模组是否也出现在冲突名单里）。为此写了专门的提示词，
要求按「能不能让游戏正常启动」排序，而不是按冲突数量。

界面会显示**本次实际有数据的来源**，你能自己判断结论考虑了多少东西。

### 5 · 支持 GPT-6 Sol / Luna 等推理模型

新增对推理模型的支持：`gpt-6-sol`、`gpt-6.1-sol`、`gpt-6-luna`，
以及原有的 o 系列。

**这里其实修掉了一个"选了就报错"的模型。** 模型列表里一直有 `o4-mini`，
但请求里无条件带着 `temperature` —— 而推理模型**拒绝采样参数**，
它们用 `reasoning_effort` 控制思考深度。混着发会直接 400，
而错误信息看起来像网络问题，很难往参数上想。

现在会自动识别推理模型：

* `o` + 数字开头（o1 / o3 / o4-mini / o5…）
* `gpt-6` 开头（Sol / Luna 家族）

用**前缀匹配**而不是写死白名单，所以以后出 `gpt-6.1-sol`、`o5`
不用等更新就能用。

设置页「参数」多了「思考深度」下拉（none / low / medium / high /
xhigh / max），对普通聊天模型无影响 —— 它们照旧用温度。

> 说明：`gpt-6-sol` 的 1.05M 上下文对本工具是**过剩的**。
> 当前发给 AI 的排查材料约 25K token，用 200K 上下文的中端模型
> 就能胜任。Sol 的优势在复杂推理，不是长度。

### 6 · 修复：安装器把文件倒进盘根目录

有人反馈「安装位置换成 `D:/` 后，文件直接散落在 D 盘根目录」。
查下来是安装器的一个真实缺陷，连带挖出两个相关问题。

#### ① 选定的位置被当成了落地目录

界面上写「安装位置」，用户自然会填 `D:/`、`D:\Games` 这类**父目录**。
而安装器直接拿它当落地目录，于是程序本体、卸载程序、图标全扔在盘根 ——
既难看，也和「卸载要删哪个目录」对不上。

现在统一换算：**在选定位置下创建以程序名命名的文件夹**

```
D:/                   →  D:/StellarisModDoctor
D:/Games              →  D:/Games/StellarisModDoctor
D:/StellarisModDoctor →  原样（已经是目标目录，不重复套）
```

界面上另加一行实时提示「实际安装到：…」—— 填完就能看到文件会落在哪，
不用猜。判据是「最后一段是否已经等于目录名」，所以**重装不会变成
`…/StellarisModDoctor/StellarisModDoctor`**。

#### ② `--dir <路径>` 被静默忽略

命令行解析原先只认 `/D=路径` 这种等号写法。传 `--dir C:/x` 时，
那个参数被当成"不认识的参数"**默默丢掉**，然后装到默认位置 ——
而返回码还是 `0`。调用方以为装到了指定目录，实际没有。

「成功但其实没按你说的做」是最难排查的一类问题，所以三处都改了：

* 空格与等号两种写法都认（`--dir X` 与 `--dir=X`）
* **不认识的参数直接报错退出**（非零返回码），不再静默忽略
* 补上 `--no-desktop` / `--no-menu` / `--purge` / `--keep-data`
  的规范写法（以前只有 `/nodesktop` 这类斜杠形式）

> 顺手印证了这条校验的价值：我自己的清理脚本写了 `--keep-data`，
> 它当时还不是合法参数，于是被拦下并报错 —— 而不是像以前那样
> 静默忽略、把用户数据一起删掉。

#### ③ 测试会卸载你真实安装的版本

`install_test.py` 走的是完整的「安装 → 校验 → 卸载」，而卸载会删快捷方式、
删注册表项、删程序目录。它**不加参数时用的正是 `default_install_dir()`
—— 也就是你真实装的那一份**。于是跑一次测试，桌面上的「熵光矩阵」就没了。

已改为：默认永远用临时目录；真实目录必须显式 `--real` 才碰，
且 `--real` 模式下**跳过卸载**，不拆你的环境。

> 顺带说明：用户数据（配置、主题、备份、API Key）在卸载时**默认保留**，
> 所以上述问题没有丢任何数据 —— 这一点原本的设计是对的。

### 7 · 修复：安装包单独下载时装不上

> **这个问题在最初发布的 v1.0.1 里存在，现在已修好并重新上传。**
> 如果你之前下载过，请重新下一份 —— 安装包从 10.3 MB 变成 22.5 MB，
> 因为现在把程序本体也包了进去。

有人反馈：选完安装位置后提示「安装失败：找不到 StellarisModDoctor.exe」。

原因是打包配置只把图标塞进了安装包，**没塞主程序本体**；
而查找逻辑又只认"安装包旁边那个文件"。也就是说：
**从同一个文件夹里双击没问题，单独把 Setup.exe 拿出来就装不了。**

这个缺陷在开发机上完全复现不出来 —— 构建目录里正好躺着主程序，
顺手就找到了。我的验证脚本也从那个目录跑，把问题整个盖住了。
**典型的「我的验证环境不等于用户的下载环境」。**

修复：

* 打包时把主程序嵌进安装包 → **下载一个文件就能装**
* 查找顺序把 PyInstaller 的临时解压目录放在第一位
* 新增 `tools/probe_setup_isolated.py`：先把 Setup.exe **复制到一个空目录**
  再装，这就是用户的处境。它在旧包上确实报同样的错，新包上通过。

### 8 · 修复：扫描范围忽略播放集

有人反馈：「我只想排序，怎么总是改我选的 mod？我有好几个播放集，
想玩不同玩法，结果一扫描就是我订阅的 mod 全部一起弄了。」

两个问题叠在一起：

**① 扫描范围是「有文件的都扫」** —— 不看是否启用、属于哪个播放集。
用户只装了 20 个想玩，工具把他订阅的九十多个一起扫、一起排、一起报冲突，
排序结果还把他精心挑的那套冲掉了。

**② 播放集启用状态互相覆盖** —— 读取时没按播放集过滤。
`playsets_mods` 表每行是（播放集, 模组, 启用, 位置），
用户有多个播放集时同一个模组会出现多行，后写覆盖前写，
结果几乎全是"启用"。

修复：

* 扫描默认只取**当前活动播放集里启用的**模组（就是启动器里你选的那个）
* 想扫全部，可在设置里打开「扫描全部模组」
* 读取启用状态时按活动播放集过滤；读不到时退回"每个模组只取一行"，
  不再让多个播放集的开关互相踩

实测本机：全部有文件 76 个 → 当前播放集 74 个。

### 9 · 新增：播放集选择与重命名

有人问：「我有好几个播放集，想玩不同玩法，结果一扫描就是我订阅的
mod 全部一起弄了。」

现在「模组列表」页顶部多了一个**播放集选择器**：

* 下拉里列出你启动器里的所有播放集，标注每个的启用数 / 总数
* 当前游戏会加载的那个标着「游戏当前」
* 换一个，扫描 / 冲突 / 排序全都跟着那一套走 —— 不必先去启动器切
* 旁边的「重命名」可以直接改名

**重命名只改名字，不动 id。** id 才是工具和游戏识别播放集的凭据，
所以改名之后工具认得、游戏也照常加载，只有你按名字认的那套变了。

改名会写你的启动器数据库，所以做了：**先备份** → 事务写入 →
失败回滚；空名字、超长、和别的播放集重名都会被拒绝。

> ⚠️ 如果你在工具里选中的不是「游戏当前」那个，提示行会变黄提醒你：
> 改动会写进你选的那个播放集，但游戏要等你在启动器里切换过去才生效。
> 不写这句，很容易以为改完立刻生效。

### 10 · 播放集：自动发现多来源并算准对应

播放集不止存在一个地方：

* **官方启动器**（Paradox Launcher v2）—— `launcher-v2.sqlite`
* **Irony Mod Manager**（第三方）—— 它自己的 JSON 数据库

而同一套配置在两边的**名字和数量都可能不一样**。实测本机：

```
官方库：「IronyModManager」 74 条 / 74 启用
Irony ：名字就叫「1」       76 条 / 已选中
```

现在两处都自动读取，并且用**工坊 id 集合的重合度**（≥80%）判断
哪些是同一套 —— 不用名字，因为名字会变（你能改名、不同工具起不同名），
id 不会。

界面上同一套会互相标注：

> 正在分析「IronyModManager」（官方启动器，74/74 个模组启用）
> ↔ Irony Mod Manager「1」是同一套（工坊 id 一致，只是两边名字/条目数不同）

**选了哪个来源，就按哪个来源的数据解析。** 选 Irony 的「1」，
启用状态和加载顺序都取 Irony 的 `ModIds` 列表（那顺序就是它合并的顺序），
实测 76 个启用；选官方库的，就是 74 个。不会串。

> Irony 的播放集**不支持在本工具里改名** —— 那要写它自己的数据库，
> 结构复杂，直接动有损坏风险。请在 Irony 里改。官方库的可以改，
> 只改名字不动 id，先备份、事务写入、失败回滚。

### 11 · 优化：AI 生成的界面主题会校验对比度

之前只检查「是不是合法的 `#rrggbb`」。所以模型给出
`文字 #333` / `背景 #111`（几乎同色）也会被当成成功，
用户拿到一套**字都看不见**的界面，还以为是自己不会调。

现在按 WCAG 标准检查所有会"叠在一起看"的配对：

| 配对 | 最低对比度 |
| --- | --- |
| 正文 vs 背景 | 4.5 |
| 次要文字 vs 背景 | 3.0 |
| 按钮文字 vs 按钮底色 | 4.5 |
| 状态色（成功/警告/严重/信息）vs 背景 | 3.0 |

不达标时**自动修正**而不是报错——把**前景**往背景的反方向推
（浅底压暗、深底提亮），背景一律不动（动背景会毁掉整片观感）。
修不到目标会如实说明"仍有 N 处偏低"，不会假装成功。

实测：故意造的全暗主题 8 项不达标 → 0 项；浅色主题 7 → 1。

### 12 · 修复的问题

其中几个此前一直存在、但不报错，所以很难发现：

* **崩溃页整张表空白** —— `data-i18n` 标在含子元素的标签上时，
  翻译机制会清空该元素的子节点，`#crashSub` 消失后渲染函数抛异常。
  送命令按钮也是同一个原因。
* **崩溃诊断信息为空** —— 取值用的键名与解析结果对不上，
  「异常类型」「异常信息」永远是空标签，AI 拿不到崩溃原因。
* **调用栈丢失帧号** —— 同一个函数名重复十几遍，看不出崩溃点。
* **语言有两个来源** —— localStorage 与配置文件互相打架，
  改配置也可能改不回来。
* **扫描结果一离开页面就消失** —— `load_mods()` 会清空扫描报告，
  切到模组列表就没了（联机校验同样受影响）。
* **任务栏提示不更新** —— 局部变量遮蔽了翻译函数。
* **严重度标签切换语言后不更新** —— 模块级常量在脚本解析时求值一次。
