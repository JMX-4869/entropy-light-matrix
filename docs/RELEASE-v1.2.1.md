## 熵光矩阵 1.2.1

修的是**「按提示关掉冲突模组之后，游戏还是起不来」**。

这不是排序算法的问题，是写库那一段的三处代码级错误。界面上看着改了，磁盘上其实没改对。

---

## 1. 播放集写错位：分析的是 B，写进去的是 A

工具内部给播放集用的键带来源前缀，形如 `paradox:<uuid>`；而启动器数据库里 `playsets.id` 只存裸 uuid。

旧代码拿带前缀的整串直接去查 `id`，永远查不到，然后**静默回落到 `isActive=1` 的那一套**。

结果：你选了播放集 B 做分析、点了应用，写进去的是活动播放集 A。界面上你那一套一点没变，另一套被改了。

现在：

- 键先剥前缀再查库
- **查不到就报错，不再回落到活动播放集**
- Irony Mod Manager 的播放集直接说明「不在 Paradox 数据库里，无法写回」

> 这一条也解释了之前那个「写回 playset 失败」——查不到的原因就在这里。

---

## 2. 点了「保留」，模组却被挪到加载顺序最后

求解器把「建议禁用」的模组**全部**从顺序里剔除了（不只是你确认关的那些），写库时再把「你选择保留」的追加到队尾。

核心框架或汉化一旦被建议禁用、你选了保留，就被扔到最后 —— 覆盖关系整个反过来，**比不动还容易崩**。

现在：没确认关闭的，保持原来的相对顺序，不会被挪到队尾。

---

## 3. 写库时悄悄删模组

`write_playset()` 的 `disabled` 参数以前签名收下了、函数体里**一次都没用**，启用状态全靠「在不在 order 里」隐式表达。三个后果：

| 现象 | 原因 |
| --- | --- |
| 有模组从播放集里直接消失 | 解析不到的模组被 `DELETE` 之后不再插回去 |
| 关掉的模组想重新勾都找不到 | 关闭写的是「删行」，不是 `enabled=0` |
| 播放集被写成残缺状态还照样提交 | 对不上时只记一行「N 个模组无法找到」，然后 COMMIT |

现在：

- 关闭写成 `enabled=0`，**行保留**，启动器里还能勾回来
- 有模组对不上就**整笔回滚，一个字不写**
- 位置连续，不留空洞

---

## 附带：两处一致性问题

同一个病的另一半：

- **`write_dlc_load()` 新增 `keep_extra`** —— 库里还启用着的模组，`dlc_load.json` 里也必须留着。否则就是「启动器里勾着、游戏里不加载」，这种分裂状态最难查。
- **写库失败时不继续写 `dlc_load.json`** —— 避免一边改了一边没改。
- `smd/app.py` 里 12 处「应用后刷新清单」补上了 `playset_key`，以前刷新会退回活动播放集，用户刚改完的那套在界面上当场消失。

---

## 还没修的（列出来免得以为是修好的）

- 关掉一个被别的模组依赖的库之后，没有反向依赖复查
- apply 写完没有回读校验
- 冲突里的 `autofix` / `fix_hint` 是死元数据，没有执行器，界面也没有「按冲突项修复」的入口
- `monitor.py` 有崩溃监测，但崩溃信息不回灌进分析

这四条都得动求解器和界面，不是换参数能改的，留着以后。

## 升级提醒

**装完这个版本之后请完全退出再重新打开。**

界面用了 WebView2 的持久缓存，旧进程还在跑的时候新界面不会被加载。如果发现界面没变化，删掉这个目录再启动：

```
%LOCALAPPDATA%\StellarisModDoctor\webview\EBWebView
```

**打完补丁记得先关掉 Paradox 启动器再操作。** 它占着数据库的时候写不进去，工具会提示，但先关更省事。
