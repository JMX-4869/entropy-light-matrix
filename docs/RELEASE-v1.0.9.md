# v1.0.9

这版动的都是**加载顺序**——模组该怎么排，以及 AI 生成的补丁为什么不靠谱。

## 一、按作者写的要求排序

**症状**：`! Core Framework of Kasako`（小伞框架）被排到**第 1 位**（最前），
而它的工坊描述明确写着：

```
排序
必须在【UI Overhaul Dynamic】后面
必须在【暗蓝科技UI】后面
其他mod无排序需求
```

用户实报：「上来把小伞框架放最上面没绷住，预期是几个 mod 配置文件和 ui 修改文件在伞框架上面。」

**根因**：排序要求只写在**工坊页面的描述**里，`descriptor.mod` 只有 name/version/tags。
旧版靠「名字里有没有 framework」定层，把它当底座排最前——**从没读过描述**。

**改法**：新增三个模块。

| 模块 | 做什么 |
| --- | --- |
| `sortreq.py` | 解析描述里的排序要求 |
| `modrole.py` | 多信号加权定位 |
| `workshop.py` | Steam 批量拉描述 |

**防误判**（这是最要紧的）——描述里 95% 是功能介绍，到处是 mod 名字。三道闸：

1. **只认「排序」小节**：先定位小标题，只解析它到下一个标题之间的内容。整篇乱扫必然误判
2. **句子里必须有排序词**（后面/前面/after/before）
3. **否定词直接丢弃**（无排序需求/无所谓顺序/no load order）

「设置面板支持 —— [Gigastructural Engineering]」这类**不会被当成排序要求**。

**开发中修掉的五个坑**，每个都能让功能静默失效：

· `<img=url>` 是自闭合的，没有 `[/img]`，非贪婪正则一路吞掉了整段 Sorting
· `[url=...]UI Overhaul Dynamic[/url]` 里的**文字是排序目标名**，不能当标签删掉
· 作者写 `Kasako's Core Framework`、工坊标题是 `! Core Framework of Kasako`——**词序相反**，精确和包含匹配全空
· 扫描后约束涨到 671 条而成环，环处理只按分层重排，把跨层的作者要求甩到前面
· `【B】` 这种单字符名字被 `{2,80}` 卡掉

**实测**（96 个模组，76 个有描述，2 个有明确排序要求）：

```
UI Overhaul(26) < Dark Blue UI(27) < 伞框架(28) < GameRules(52)
```

三条作者要求全部满足。

## 二、智能定位

不再是「一串 if/elif 先命中先算」，改成**多信号加权**：

| 信号 | 权重 | 为什么可信 |
| --- | --- | --- |
| 目录结构 | 1.5 | 唯一骗不了人的——只有 `localisation/` 就一定是汉化 |
| 名称关键词 | 1.0 | 作者自己的命名习惯 |
| descriptor 的 tags | 0.8 | 作者自己填的分类 |
| 依赖关系 | 1.2 | 依赖别人的不可能是最底层 |

每个信号都留证据，输出置信度。**低置信的从 18 个降到 5 个**（96 个里）。

`!!!Universal Resource Patch` 单独走「决定性名称」通道——它的形状（只有 `interface/`、
tag 写 Fixes）和 UI 模组、补丁都像，投票会被稀释到 0.45，而它恰恰是全社区公认的底座。

## 三、AI 补丁会自己改了

**旧流程**：生成 → 解析 → 校验 → 返回。**校验没过就结束**，
那个错误从来没告诉过 AI。于是同一个错它每次都犯。

**现在**：校验失败时把错误结构化地喂回去——

```
你上一版补丁有 2 个阻塞问题，请修正后重新输出完整补丁。
1. [error] 引用了不存在的定义 X —— 在 a.txt
     提示：用游戏里实际存在的
```

必须给 `where` 和 `hint`，只说「校验失败」模型只会换个姿势再错一遍。
最多 3 轮。修不了的让它**去掉**，不要编造名字——编出来的名字一定不存在，
这正是最高频的那类错误。

## 四、它会记住自己错在哪

把阻塞问题**归类**后统计频次，下次生成时把高频的注入提示词：

```
## 你以前在这些地方栽过（同类错误反复出现，这次请避开）
· 出现过 3 次：**引用了不存在的对象**
· 出现过 3 次：**括号不配平**（检查第 42 行）
```

**归类是关键**：`引用了不存在的定义 acot_ship_a` 和 `foo_bar_def` 是同一个毛病，
不归并就每条只出现一次，学不到东西。

边界：只记 fatal/error（warn 太杂会污染）；同类 ≥2 次才注入；
90 天后过期（游戏更新后旧教训可能不适用）；记模式不记原文。

## 五、顺带修的

· **卸载轻量版会删掉完整版的桌面图标** —— `remove_shortcuts` 用 `APP_NAME`（两产品共用）
  拼路径，而创建用的是 `DISPLAY_NAME`。现在删之前会核对 `.lnk` 指向的 exe 是不是本产品的。
· **本地 mod 误报「目录不存在」** —— `.mod` 里的 `path="mod/xxx"` 是**相对用户数据目录**的，
  之前没拼，`is_dir` 按当前工作目录判，永远落空，还反过来劝用户关掉正常的 mod。
· **学习版/便携版找不到用户数据** —— 新增在游戏目录附近查找。
· **扫描撞上目录成环会崩** —— 加 40 万条目 / 64 层上限，Windows junction 不是符号链接，
  `follow_symlinks=False` 挡不住它。
