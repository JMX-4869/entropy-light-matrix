## 熵光矩阵 1.2.3

这一版是照着 B 站评论改的。

---

## 1. 「递归超限」不再让整个扫描挂掉

Paradox 脚本正常嵌套很少超过 30 层，但工坊里有机器生成或损坏的模组能写出上千层。

`iter_leaf_keys()` 和 `canonical_text()` 两个递归函数**都没有深度保护**，撞上就是 `RecursionError`，整次扫描直接失败。

现在：加 60 层上限，超过就把当前节点当叶子收下，path 上不再往下钻。

**代价说清楚**：超过 60 层的部分会被合并成一个摘要，极深层里如果有细微差异可能漏报冲突。60 层对正常的群星脚本远远够用，这个取舍是「宁可漏掉深层几个键，也不能让整次扫描抛异常」。

压力测试：2000 层的合成结构，两个函数都正常返回。

## 2. 冲突检测页写明「到底扫了哪些模组」

有评论说「感觉他是把整个订阅的模组扫一遍，而不是只扫描播放集中的模组」。

**其实一直是只扫播放集里启用的**（`scan_all_mods` 默认关闭，走 `lib.enabled()`），但界面上一个字都没提，看不出来。

现在冲突检测页标题下面多一行：

```
扫描范围：74 / 96 个模组　只扫当前播放集里启用的那部分。
想连未启用的也扫？去设置打开
```

点了开着 `scan_all_mods` 的情况会显示：

```
扫描范围：全部 96 个模组　（设置里开着「扫描全部模组」）
```

这个数从后端 `conflicts.stats` 带上来，不受界面状态影响。

## 3. 播放集选择器说清楚「不用导入 JSON」

另一条评论问「用的第三方启动器，能导入播放集 json 排列吗」。

**Irony Mod Manager 的播放集是自动发现的** —— 读它自己的 JSON，列出名字和数量，跟官方启动器的播放集并排显示，选中就按它的启用状态和顺序走。不用手动导入。

但这个行为在界面上完全没写。现在选择器的 tooltip 直接说明：

> 要分析的播放集。官方启动器和 Irony Mod Manager 的都会自动列出来，不用导入 JSON
