# 熵光矩阵 · 宣传片分镜脚本

**规格**：1920×1080 · 30fps · **73.5 秒** · 含群星风配乐（无配音）
**成品**：`promo/熵光矩阵-宣传片-1080p.mp4`（h264 + aac 48kHz，16 MB）
**素材**：全部为软件**真实界面截图**（2560×1440 超采样 → 1080p）
**音乐**：程序合成（`tools/make_music.py`），版权归项目所有

---

## 一、视频（v2 四项优化）

### 1. 超采样渲染

渲 **2560×1440** 再降到 1920×1080。所有文字与细线边缘明显更锐利 ——
直接渲 1080p 的话小字号会发虚。倍率取 4/3，再往上肉眼看不出来、
时间却线性增长。

### 2. 场景交叉淡化

v1 是**硬切**，观感廉价。现在相邻场景有 **0.5 秒叠化**。

实现方式（值得说明）：单路 ``-i`` 输入没法做转场——转场需要
"两段画面同时存在"。所以把同一路帧输入拆成 11 份，
各自 ``trim`` 出自己的帧区间，再用 ``xfade`` 串起来。
好处是**每个场景的帧区间精确到帧**（由 `manifest.txt` 给出），
不会因浮点累加漂到半帧。

总长效应声从 78.5 变成 **73.5 秒**：10 次转场各吃掉 0.5 秒重叠。

### 3. 按素材比例分别裁切

这批截图比例不统一：

| 素材 | 尺寸 | 比例 |
| --- | --- | --- |
| 总览 / 冲突 / 顺序 / 补丁 / 档案 | 1384×861 | 1.607 |
| AI 接管 / 崩溃报告 | 1384×911 | 1.52 |

v1 统一按 16:10 裁，对后两张会切掉底部。现在对窄图改
**顶部优先**（`top_bias=0.0`），标题栏完整保住。

### 4. 截图轻微锐化

降采样会让细节变软，补一点 UnsharpMask（半径 2、强度 58%）找回来。

### 排版要点（试出来的）

- **文字放截图旁边，不压上去**：压上去必然挡住界面细节，
  而界面正是要展示的东西
- **截图裁一刀再放大**：原始截图直接铺会缩得很小、界面看不清
- **要点字数要控住**：第一版有一条「深度解析 46715 个文件（模组 +
  原版 + DLC）」折行了，尾巴掉到第二行很难看。改成两条短句
- 截图带圆角 + 描边 + 背后外发光，像"贴在深空里的一块屏幕"

## 二、音乐（重做为群星风）

### 为什么从头重做而不是调参

第一版是"通用太空环境音"：正弦垫音 + 缓慢起伏，没有调性重心、
没有声部层次、没有行进感。能当背景，但**不像群星**。

### 《群星》配乐的听感特征 → 合成上的对应

| 特征 | 实现 |
| --- | --- |
| 管弦乐编制 | 弦乐持续音铺底 + 铜管中段进入，不是单纯合成器 pad |
| 缓慢庄严的行进 | 和声每 6 秒一换（约 10 BPM），低音像心跳一步步走 |
| 调性明确但旋律克制 | A 小调，长音多音符少，靠和声色彩与配器推进 |
| 空间感很重 | 6 段延迟模拟大厅混响，尾巴逐段变暗 |
| 动态起伏大 | 从几乎只有低音的寂静堆到全奏 |

### 解决"不像管弦乐"的根本问题：换掉正弦

第一版最大的短板是**纯正弦没有泛音**，所以做不出弦乐和铜管的音色。
这版换成**带限锯齿波**（谐波叠加、1/k 衰减）+ 多路微失谐：

| 音色 | 做法 |
| --- | --- |
| 弦乐群 | 6 路 ±0.8% 失谐锯齿 + 0.35% 颤音（完全齐奏反而像合成器） |
| 铜管 | 锯齿 + 强低通包络（起音 4kHz 迅速收到 900Hz 的"blat"）+ 吹奏噪声 |
| 拨弦 | 低通快速下扫（泛音先亮一下再消失，这是拨弦的本质） |
| 低音 | 正弦 + 二次谐波（纯正弦在小喇叭上完全听不见） |

### 结构

| 时间 | 内容 |
| --- | --- |
| 0–6s | 只有低音与弦乐，留白 |
| 6–30s | 弦乐铺开，拨弦动机零星进入 |
| 30s+ | **铜管进入**，张力上来 |
| 42s+ | **定音鼓**进入，配合画面最"重"的几屏 |
| 66s+ | 收束回低音 |

脉冲类乐器（铜管、定音鼓）刻意**延后进入**——一上来就打拍子会像广告。

### 一个被客观指标抓出来的严重错误

音乐没法靠读代码判断对错，所以做了**声道相关性**测量。第一版：

```
左右相关性 -0.139     ← 几乎完全反相！
```

这不是风格问题。**单声道播放时会互相抵消**——手机外放、部分播放器
会明显变小声甚至整段消失。

修的时候我连错两次，最后**做对照实验**（拿真实素材测各种做法）：

| 做法 | 相关性 | 单声道损失 |
| --- | ---: | ---: |
| 整条右声道延迟 14ms | 0.455 | -1.38 dB |
| 整条右声道延迟 7ms | **-0.386** | **-5.13 dB** |
| 左右各延迟 0 / 2.5ms | 0.305 | -1.85 dB |
| 左右不同混响 | 0.933 | -3.49 dB |
| **混入 14ms 延迟占 25%** | **0.968** | **-0.55 dB** ✅ |

结论两条：

1. 延迟的必须是**一小部分信号**，不能是整条声道
2. 延迟量要**避开低频周期**——7ms 恰好在 110Hz 附近反相，
   所以它比 14ms 还差

另外混响的左右两路也必须用**同一组延迟**：给不同的延迟模式
相关性看着还行（0.933），但单声道损失 -3.49 dB，
因为两路混响尾巴互不相关，相加时按功率而非幅度叠加。

现在实测 **0.948 / -0.55 dB**，宽度和单声道兼容都拿到了。

### 频谱分布

```
低频 <200Hz    33.8%
中低 200-800   43.9%     ← 主体
中频 800-3k     9.5%
中高 3k-8k      2.8%
高频 >8k       10.0%
```

整体偏温暖。**如实说明**：我试过三档噪声滤波想把能量往 3~8kHz 挪，
但用一阶差分近似带通本来就粗（斜率太缓），三档下来 `>8k` 反而更高。
再往下调属于瞎试，所以停手——取分布最均衡的一档。
作为"不抢画面的铺底"这个分布是可用的。

### 客观验证

| 指标 | 结果 |
| --- | --- |
| 削波样本 | **0**（峰值 0.692） |
| 动态范围 | 3.62x（比 v1 的 1.6x 更有起伏，才像配乐） |
| 左右相关性 | 0.948（单声道兼容） |
| 采样率 | **48000Hz** — 48000/30 = 1600 整，与帧率整除，音画严格对齐 |
| 成品解出音频 | RMS 0.046，**确认有声**（这步不能省） |

音乐压到 **0.55** —— 背景音乐盖过画面文字就本末倒置。

## 四、怎么改

```powershell
# --- 快速看排版（约 30 秒，每场首/中/末帧）---
python tools/make_promo.py --quick
#   → promo/check_NN_f####.png

# --- 完整重建 ---
python tools/make_promo.py                 # 渲 2355 帧（约 15 分钟）
python tools/make_video.py                 # 编码（带转场）
python tools/make_music.py                 # 合成音乐
python tools/mux_music.py                  # 混音（几秒，画面直接 copy）

# --- 常用变体 ---
python tools/make_video.py --crf 16        # 更高质量
python tools/make_video.py --no-xfade      # 硬切（对比用）
python tools/make_music.py --seconds 60    # 换个长度
python tools/mux_music.py --music-vol 0.4  # 音乐更小声
python tools/check_music.py                # 音乐客观指标
```

**为什么拆成四步**：帧、画面编码、音乐、混音各自独立。
换音乐不该重编画面（`mux_music.py` 用 `-c:v copy`，几秒完成），
改码率不该重渲帧，调排版不该等编码。

## 五、注意

`font()` 依次找 `msyh.ttc`（微软雅黑）→ `msyhl.ttc` → `Deng.ttf`
→ `simhei.ttf`。**Pillow 自带的默认位图字体不含汉字**，
找不到中文字体时中文会显示成方块 —— 换电脑跑这些脚本时留意。
